# 手册摘要证据与写作规则

来源：HB-001，2023—2025手册案例物理页69、98、134、161、188、216、244、275、351、391、414；逐页渲染见 `research/handbook/abstract_pages/`，视觉初审见 `research/handbook/ABSTRACT_VISUAL_AUDIT.md`。样本只代表手册收录，不能推及全部高奖论文。

## 已观察到的写法

- 四问摘要常用逐问分段：HB-02、04、05、06、08、11。段首映射问题，读者容易定位，但需避免重复“for question”。
- 非逐问标题式结构也存在：HB-03以主题小标题组织，先报局部结果再综合；HB-07连续分问题段；HB-01段首突出方法/结论。
- 正文粗体不构成统一标准：HB-02/03较多粗体，HB-07/09基本连续正文；HB-04强调模型/方法。故“每问标题都必须加粗”“所有模型名必须加粗”均不受该样本支持。
- HB-05提供数据分类计数和评价指标；HB-07摘要覆盖多个数据层级及模型链。读者能看到实际分析对象和输出，比堆模型名更有信息。

## 暂定写作规范

1. 首段用一至两句交代问题对象、数据/机制和研究目标；不把背景泛论挤占摘要。
2. 以子问题或逻辑阶段分段；题目多时可按共享数据与模型依赖合并，不硬凑一问一段。
3. `For Problem 1`可以作为导航，但是否加粗由可读性决定；标签不提供数学信息，版面拥挤时可改成简洁小标题。
4. 模型名只在首次引入且承担方法贡献时强调，避免加粗模型清单。
5. 定量结果应报告量纲、比较基线或情境；只有经实际运行和核验后方可写入。可少量加粗关键结果，但无须全加粗。
6. 创新写明“做了何种数学改变、解决什么既有限制”；验证写清留出数据、基准、误差/不确定性或稳健性，不以“proved excellent”替代证据。
7. 关键词放摘要末尾；标签格式服从官方模板。

## 原创结构骨架

### 1—2个子问题
问题与数据目标 → 方法及假设 → 关键实测结果/验证 → 局限与决策含义。

### 3—4个子问题
问题结构与数据 → 按依赖关系分2—4段：每段交代输入、模型、输出及验证 → 综合结论和边界。

### 5个以上子问题
按主题/共享模型组成模块而非逐题列流水账 → 对每模块交代方法和可验证输出 → 总结模块间连接、决策含义和主要不确定性。

模板不得预填实验数字；使用 `[经验证的结果与单位]` 等占位符，并在提交前替换或删除。
