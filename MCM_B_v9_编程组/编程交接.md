# BUS2003 · MCM B v9 编程交接

## 运行与文件

本目录是编程组的独立工作副本。数值模型沿用建模组交付的 v9，15 个归档所列源码文件的 SHA-256 一致。新加入的 `programming_handoff.py` 负责归档对照和论文数据导出，`plot_handoff.py` 负责出图。

在本目录用 Python 3.12 的虚拟环境运行。已实际使用的三项依赖版本与建模组记录一致。

```bash
python -m pip install numpy==2.3.5 scipy==1.17.0 matplotlib==3.10.8
python run_v9.py && python programming_handoff.py && python plot_handoff.py
```

如相邻目录仍保留建模组归档，可额外执行 `python programming_handoff.py --compare-with ../MCM_B_v9`。完整重算从物理接口、供水、联合策略和敏感性计算进入独立验证，运行成功才会写 `results/run_record.json`。本次 macOS arm64 运行约 34 秒，五个阶段退出码均为 0。

## 新增 Q2 与 Q4–Q5 分析

数值基线复现后，在本目录运行以下命令。两支脚本从已经通过独立校验的 v9 结果取默认任务和候选范围。

```bash
python fault_attribution_v9.py
python joint_screening_v9.py
```

**Q2 单项故障影响。** [结果表](results/supplemental/q2_fault_attribution.csv)含完整故障基线和七种反事实情景。每次只把一个故障参数设为零，保持其他故障支持、时滞和推进剂损失假设。每种情景的第一行固定原混合方案的 29.063479% 电梯份额，第二行从 v9 的 5% 网格、当前情景的平衡份额和原份额中选交付工期上界最短者。遇到相同工期时先比中央情景预算，再比电梯份额。表中工期以一般建设物资交付为终点。取消地面发射场额外停运后，原份额仍受电梯链约束，建设交付上界为 300.72 年。重选 23.69% 电梯份额后，上界为 245.32 年，中央建设预算从基线的 85.26 万亿美元升至 86.74 万亿美元。各情景的差值按与同一基线比较来理解。

**Q4–Q5 入住和排放联合筛选。** [结果表](results/supplemental/q4_q5_joint_screening.csv)使用默认任务和故障条件下的 2,904 个完整策略。默认采用中央系数，把原 v9 的七档入住期限与九档排放代理上限交叉成 63 组。逐组保留入住时间上界和排放代理量均不超过限额的候选，再选预算最低者。同预算时依次选入住上界较短、排放代理量较低、决策字段排序靠前的方案。表中选中行含策略编号、建设和备料份额、供水设计及三项指标。零候选表示当前目录在该组限额下为空。

可把示例限额换成论文采用的情景。`--deadline-years` 从项目开始计时，每年 365 天。`--emissions-cap-gt` 的单位是十亿吨 CO₂ 当量的模型代理量，1 Gt 等于 \(10^{12}\) kg。多值参数按所有组合筛选。自定义结果默认写入 `q4_q5_joint_screening_custom.csv`。

```bash
python joint_screening_v9.py --deadline-years 350 --emissions-cap-gt 1.99 2.81
```

示例中，350 年和 1.99 Gt 的联合条件下，当前候选目录为空。350 年和 2.81 Gt 的联合条件下，有 251 个候选，最低中央预算约为 86.87 万亿美元，入住上界约为 321.99 年，排放代理量约为 2.797 Gt。[自定义示例结果](results/supplemental/q4_q5_joint_screening_custom.csv) · [补充复现清单](results/supplemental/复现清单.json)

## 编程接口与口径核对

- `physics_v9.py` 产生轨道与载荷接口。`construction_v9.py` 提供固定运力下的交付证书，包括货损、补发与有限备用船。
- `water_v9.py` 产生预存水与回收补给选项。`joint_v9.py` 将建设、设备到货、备水和入住按阶段合并。`cost_environment_v9.py` 将资源数量转换为情景预算和排放代理量。
- `sensitivity_v9.py` 在共同候选规则下做压力分析。`verify_v9.py` 和 `phase_audit_v9.py` 独立回代数量、阶段和选优结果。
- v9 工期是给定支持条件下的充分上界，金额是给定单价情景的保守承诺预算，环境量仅覆盖已列运行排放代理。外部仓储与接收可用性、维护和实际单价仍是模型条件。
- 建设量以联合程序的实际账本为准。`joint_v9.py` 先计算 1 亿吨一般建设物资，再追加供水设备。`water_v9.py` 的 `hardware_service_life_assumption` 有一句关于从一般建设量扣除已含设备的说明，与联合程序和建模说明的口径有歧义，留给建模组确认文案。

独立技术质检与人工作业签核分开记录。队员应在确认本地运行、可复述关键口径后填写证据链中的人工核验结果和责任人。
