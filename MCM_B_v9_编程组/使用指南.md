# 数学建模 Skill 使用指南

> 本指南说明「math-modeling」Skill 的使用边界与交付物用途。**使用本 Skill 前请先阅读本指南**。

## 一、本 Skill 的定位

本 Skill 是完成数学建模**全流程的辅助工具**，分三个阶段：

- **建模手**：理解题目、拆分子问题、选择模型
- **编程手**：实现代码、运行求解、生成图表
- **论文手**：撰写论文、整理结果、生成 Word/LaTeX

它帮助你把一道数学建模题从读题推进到论文初稿，供**学习与研究参考**。

## 二、交付物使用边界

> ⚠️ **本 Skill 生成的所有内容不能直接作为参赛作品提交。**

| 交付物 | 性质 | 提交前必须做的事 |
|---|---|---|
| `题目分析报告.md`、`术语表格.md` | 建模草稿 | 核对模型选择与公式，确认与题目约束一致 |
| 代码（`.py`/`.m`）、结果表（`.csv`/`.xlsx`） | 求解草稿 | 实际运行验证，核对数值、单位、边界条件 |
| 图表（`figures/`） | 结果草稿 | 核对数据来源与图注，确认与代码输出一致 |
| `完整论文.docx`（及可选 LaTeX） | **论文草稿** | **人工核对、改写后再提交**；不得原样提交 |
| `results/复现清单.json` | 复现记录 | 确认种子、参数、命令与实际运行一致 |
| `evidence_chain/evidence.json`、`evidence.md` | 决策与证据记录 | 核对每个关键选择确由队伍作出，每个关键数值和结论均能追溯 |

**使用边界摘要**：

- 生成的分析、代码、图表、论文均为**草稿/参考材料**，提交前必须由参赛队伍人工核对、改写。
- 数值、公式、图表、引用可能存在错误，须独立验证。
- 论文结构与格式最终以**目标竞赛当届官方规则和模板**为准，不能用本 Skill 输出的格式直接提交。

## 三、文件清单

本 Skill 生成的文件按阶段划分：

| 阶段 | 生成文件 | 用途 |
|---|---|---|
| 建模手 | `题目分析报告.md` | 问题理解、模型选择与分析 |
| 建模手 | `术语表格.md` | 全文术语、符号、单位统一 |
| 编程手 | `*.py` / `*.m` 代码 | 模型求解实现 |
| 编程手 | `results/*.csv` / `*.xlsx` | 求解结果表格 |
| 编程手 | `figures/raw_* process_* result_*` | 数据/过程/结果三类图 |
| 编程手 | `results/复现清单.json` | 复现所需的种子、参数、命令 |
| 全流程内部记录 | `evidence_chain/evidence.json`、`evidence.md` | 使用者决策卡、主张—证据链、跨材料一致性和人工责任记录 |
| 论文手 | `完整论文.docx` | 论文草稿（Word） |
| 论文手（可选） | `完整论文-LaTeX/` + `完整论文.pdf` | 论文草稿（LaTeX） |

## 四、提交前人工核对事项清单

> 以下每一项都应在提交前由参赛队伍逐条核对：

- [ ] **数值**：论文中所有关键数值与代码实际运行结果一致
- [ ] **图表**：所有图表编号连续、有标题、正文有引用、数据来源真实
- [ ] **公式**：公式与代码实现一致，符号与术语表格一致
- [ ] **引用**：正文引用与文末参考文献双向对应，来源真实可追溯
- [ ] **格式**：结构与格式符合目标竞赛当届官方规则和模板
- [ ] **CUMCM 2026 提交包**：`check-submission` 已直接读取最终论文和 ZIP/RAR，机器审计与队员确认均通过；不存在目录、超 30 页正文、身份信息、未列入附录的支撑文件或超 20 MB 文件
- [ ] **完整性**：所有子问题均已作答，结论有数据支撑
- [ ] **复核**：全文经队伍成员人工阅读、改写，确认符合竞赛要求
- [ ] **决策**：模型、假设、验证强度和证据口径等关键分叉已通过决策卡由队伍选择；不存在 AI 未经确认替队伍作出的核心取舍
- [ ] **证据链**：关键数值可追溯到数据、处理代码、模型、程序输出和论文/图表位置；摘要、正文、表图中的数值与单位一致
- [ ] **可解释**：队员能说明模型选择、参数来源、人工修改、核验方式和失效条件；AI/Agent 没有充当最终责任人
- [ ] **AI 披露**（目标竞赛要求时，如 CUMCM 2026）：AI 台账记录完整；正文「AI工具使用声明」位于参考文献前（未使用 AI 时采用官方固定短句，使用 AI 时为 100–180 字第三人称）；《AI工具使用详情.pdf》已生成且匿名；所有 AI 辅助的核心内容均有队员人工采纳/修改/核验记录

## 五、AI 使用与披露说明

- 本 Skill 的三阶段流程、质检 Subagent 和可选协作 Subagent 均属于 AI 工具/智能体使用。目标竞赛要求披露 AI 使用情况（如 CUMCM 2026《人工智能工具使用规定》）时，这些使用**必须**如实记入 `PROJECT_ROOT/ai_ledger/ledger.json`，并生成正文声明与《AI工具使用详情.pdf》。
- 官方要求核心建模与分析由参赛队主导，对 AI 参与内容逐项人工审查与核实。**AI 自审或另一 AI 的复核不能替代队员的人工核验**。
- 不得隐瞒 AI 使用、作虚假声明，或将未经必要人工审查核实的 AI 内容直接作为核心成果提交——这会导致取消评奖资格。
- 使用方式详见 `tools/ai_ledger/SKILL.md`。

## 六、选择题与证据链

- Skill 只把存在多个合规可行路线的关键取舍做成选择题，每次展示一个问题、2–3 个互斥选项、推荐理由、收益、代价和待补证据。
- 使用者没有选择前，Skill 不得冻结受影响的模型、运行全量实验或写入对应结论。
- 官方硬规则、引用真假、代码是否运行、数值和单位是否一致等客观事项直接校验；不会提供“忽略错误继续”的选项。
- `evidence_chain/evidence.json` 是三阶段共同维护的单一证据源；`evidence.md` 是供队伍阅读的决策与证据摘要。
- 详细逻辑见 `references/选择题与决策卡协议.md` 和 `tools/evidence_chain/SKILL.md`。
